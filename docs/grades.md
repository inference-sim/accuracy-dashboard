# Closeness grades

Generated by `orchestrator/ingest/gen_grade_doc.py` from `orchestrator/ingest/grade.py`; do not edit by hand. Design §11.3 and §11.4 define the grades. Every point gets one grade: the highest-numbered grade whose conditions apply.

## The grades

| Grade | Meaning |
|---|---|
| G1 | Exact. Every condition below was evaluated and is true. |
| G2 | Estimated. The point is scored, with every substitution named on it. A condition that could not be evaluated is one of those substitutions. |
| G3 | The run measured another release of the engine, and no function the engine ports from upstream changed between the two releases. |
| G4 | As G3, but a ported function changed; or the build is nightly or custom; or the engine has not published its list of ported functions, so that cannot be told. |
| G5 | Not scored, for one reason of the closed list below. |

A point counts toward the headline when its grade is G1 to G4. Each grade is also reported on its own: its share of the points, and its own accuracy. A figure over fewer than 10 points is shown as `too few points`.

## G1: the conditions

1. The run's engine release is the release the scoring simulator runs.
2. Each library version the run used maps to the kernel hash BLIS priced (`kernel_hash`).
3. Every field the run sets is modelled, or proven inert, and its value is in a value class the engine's evidence covers (`value_class`).
4. Every coefficient the point used is measured or calibrated, and none was extrapolated or unidentified (`coefficient_method`, `coefficient_range`).
5. The value the engine resolves for a field the run left unset is the value the run used (`resolved_differs`).
6. The simulated requests are the ones the run's client sent (`client_difference`).

## Unevaluated conditions

A condition is *unevaluated* when no source records the datum it needs. An unevaluated condition is not assumed true: the point names it as a substitution whose subject is `unevaluated`, so the point is G2 at best. A point can be G1 only when none of these is named.

| Condition | Meaning |
|---|---|
| `coefficient_range` | A coefficient lookup was extrapolated or unidentified. |
| `kernel_hash` | A library's kernel hash differs from the one BLIS priced. |
| `resolved_differs` | The value the engine resolves differs from the one the run used. |
| `value_class` | A modelled field's value is outside the value classes its evidence covers. |

A condition leaves this table when it is evaluated from data; the point then names a substitution of that kind only when it is true of the point.

## Substitutions (G2)

| Kind | Meaning |
|---|---|
| `coefficient_method` | A coefficient the point used is transferred, literature, vendor_spec, roofline, assumed or copied, not measured or calibrated. |
| `coefficient_range` | A coefficient lookup was extrapolated or unidentified. |
| `execution_mode` | The point ran in a substituted execution mode. |
| `kernel_hash` | A library's kernel hash differs from the one BLIS priced. |
| `value_class` | A modelled field's value is outside the value classes its evidence covers. |
| `estimated` | A field's value was estimated by the engine's rule (`leave_unset` or `substitute`), or a needed value the run did not record was taken by that rule. |
| `interim_status` | The run set a field whose status is `inert_unproven`, allowed only during a release plan. |
| `resolved_differs` | The value the engine resolves differs from the one the run used. |
| `client_difference` | The simulated requests differ from the ones the run's client sent. |
| `later_record` | A fact of the cluster the run's own record lacks was taken from the benchmark's later record of the same runner. |
| `router_differs` | The run's router, which BLIS does not host, was replaced by an llm-d router policy from the substrate's router table. The subject is the router the run used; the point names the table entry, the policy (one llm-d offers) and the table's evidence. |

## Other release or build (G3, G4)

| Kind | Meaning |
|---|---|
| `other_release` | The run measured another engine release than the simulator runs. |
| `changed_functions` | A function the engine ports changed between the two releases. |
| `nightly_or_custom` | The build is a nightly, a dev build, a fork or a private image. |
| `ported_functions_unpublished` | The engine has not published its list of ported functions or the diff. |

## G5: not scored

The list is closed (design §11.4). The scorer's own reason codes map onto it (`assess.G5_FOR_REASON`); a reason with no place here is an error.

| Reason | Meaning | How it is removed |
|---|---|---|
| `code_not_visible` | The engine code the build runs cannot be seen (a private image). The scorer emits no such reason today: a build it cannot resolve is G4 (nightly or custom). | Not applicable until the scorer tells a private build from a nightly one. |
| `router_unsupported` | The run was measured behind a router BLIS does not host. BLIS hosts llm-d's router only. | Host the router in BLIS (a router in inference-sim, then the scenario names it). |
| `topology_unsupported` | The deployment is a shape the scenario cannot state (a disaggregated or multinode layout the engine block cannot express). | Add the topology to the engine's deployment block and to the scorer's scenario writer. |
| `value_not_recorded` | A value the simulation needs was recorded by no source: the server log is missing, the launch artifact does not match the row, a required setting is absent, or the client's scenario cannot be replayed. | Record the value (InferenceX uploads the log or artifact), or give the field an estimation rule in fields.json. |
| `field_not_modelled` | The run set a field the engine's fields.json lists as not modelled, with rule `none`. | Model the field in the engine, or give it `leave_unset` or `substitute` in fields.json. |
| `field_unclassified` | The run set a field that fields.json lists but has not classified. | Classify the field in fields.json. |
| `engine_unsupported` | The row's inference engine is not vLLM. | Add the engine (blis-sglang, blis-trt) and its fields.json; the score then reads that engine's list. |
| `not_in_catalog` | The model, the chip's coefficients or the speculative drafter is not in the catalog or registry the simulator reads. | Add the model or drafter to the catalog, or measure the chip's coefficients, and release them. |
| `field_not_in_release` | The run set a field the engine release does not list. | Add the field to the release's fields.json, or score the point on a release that lists it. |
| `value_conflict` | Two sources of one stage record different values for a field (launch configuration against the logged arguments, or a launch node size against the runners table). | Correct the source; the harness never picks one. |
| `build_unparseable` | The run's image and log banner name no engine build at all. The scorer emits no such reason today: a build it cannot resolve is G4 (nightly or custom). | Not applicable until the scorer tells an unnamed build from a nightly one. |

## Run faults (not a grade)

A point whose scoring fails has no grade. It is listed as failed, and the run stops unless every fault is a runner limit.

| Fault | Meaning |
|---|---|
| `blis_refused` | The simulator refused a scenario the harness wrote from recorded values. A refusal for memory or time (`insufficient_memory`, `timeout`) lists the point as failed. Any other refusal stops the run. |
| `setting_differs` | The scenario written lost a value the run recorded. The run stops. |

## Reading the tables

- A comparison table (`orchestrator/baseline/compare.py`) is labelled in-sample or held-out. In-sample means no anchor list exists, so no point is held out. A table never mixes the two.
- *Blocks* counts the points a G5 reason or substitution holds back. *Alone* counts the points whose only reason it is, so fixing it alone would score them. *Demotes* counts the graded points a substitution holds below G1 (design §11.6).
- AMD (mi300x, mi325x, mi355x) and TPU points are out of scope for M2 to M4. The comparison tables count them apart from the in-scope points; the scorer's reason codes are unchanged.
